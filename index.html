How a verdict is reached

Lock

The team writes the promise, the deadline and its official page. Its wallet owns the project name, so nobody else can post for it.

Read

Anyone presses Verify. Each validator opens the live page itself.

Agree

An AI judge on every validator compares the page with the promise date and deadline, and the verdicts must match.

Settle

Kept or broken is saved on-chain and updates the Trust Score. Things shipped before the promise are marked void and give no score.

What changed in v2

Community reviewers tested v1 and found real gaps. Each one is fixed in the contract and covered by a test in tests/test_roadmap_proof.py.

Found in review

Anyone could post promises under any project name, so the Trust Score could be farmed or attacked.

Fixed

The first wallet to claim a name owns it. Only the owner can add promises. Owners can hand the name to a new team wallet.

Found in review

A promise for something already shipped (Python 3.14) resolved KEPT straight away. The creation date was never given to the judge.

Fixed

The judge now sees the promise date. Anything released before it is marked VOID and does not count toward the score.

Found in review

The same promise could be recorded twice as two separate KEPT entries.

Fixed

Same project plus same claim is rejected, even with different spacing, case or punctuation.

Found in review

No tests in the repo, and the deployed contract did not match the repo code.

Fixed

19 unit tests added. v2 is deployed from the exact repo file, and get_version() returns 2.0.0 on-chain.
